# Shared translations and first consumers (UX-01)

`src/lib/internal-tools/i18n/` is the local English/Spanish dictionary boundary. Persisted records, employee names, narratives, source files, dates, numeric inputs, workbook values and enum IDs remain language independent. No translation service or new package is used. Spanish terminology is provisional; DEC-07 still requires staff approval for final terminology, numeric examples and print language.

The internal layout mounts `InternalLanguage` once. It stores only `en`/`es` in `cr-internal-locale`, catches denied/corrupt preference storage, and renders a visible English / Español control. A locale change updates context without keying/remounting children or navigating. Manager/staff credentials remain in component memory; they never enter the preference. Switching language is not a server save.

First consumers cover the internal banner, dashboard navigation/cash summaries, bookkeeping tabs, the complete cash-out entry/gate/history/confirmations and sales/hours converter screen controls/statuses. Scheduler-specific editors, inventory/form screen adoption remains with those domain tasks; their records and public schedule behavior are unchanged. New consumers use `useInternalLanguage()` and namespaced `TranslationKey` entries. Add matching entries to both dictionaries; keep placeholders identical. Unknown runtime keys display `[key]`, never an empty control; absent parameters stay visible as `{parameter}`. Original names and input values are interpolation values, not translation keys. Source-system labels and store addresses are preserved.

Async states store message keys/parameters, not translated text. A late acknowledgment/error renders in the current language without resubmitting or clearing input. Existing legacy store failures map to stable local translation keys; arbitrary backend error text is not rendered. Server acknowledgment is shown only after the existing API returns success. This does not upgrade legacy KV or client-calculation guarantees; CASH-03/DATA-05 and their consumers own those separately. Draft repair/recovery is CASH-01/UX-05; this task only handles the locale preference's denied storage.

English remains the existing print/workbook output language pending DEC-07/UX-07. Browser `beforeprint` synchronously selects English labels without changing record values or the saved screen preference; `afterprint` restores the screen language. No paper structure, calculations, workbook cell mapping, name/narrative or output schema is changed. Print events, hidden controls and value retention are exercised locally; no staff archive/signature policy is inferred.
