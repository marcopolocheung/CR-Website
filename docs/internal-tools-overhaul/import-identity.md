On 2026-10-24 the requesting user approved: managers explicitly review employee-ID mappings, never match by name, retain inactive identities, disable hour targets; apply these defaults only to import work. This is DEC-04-IMPORT, a stable child of DEC-04. Effective for local import implementation now; activation remains separately gated. DATA-04-IMPORT is the independently deliverable reviewed import-directory slice, consumed by IMPORT-06. It persists a store-scoped directory snapshot in the existing D1 `records` employee-mapping family through DATA-05 atomic mutation/history. It does not project into or activate the future global personnel tables. IDs are explicit opaque UUIDs; a manager may reuse an independently verified shared UUID across stores. A name never chooses an identity. Inactive identities cannot be deleted from a saved directory; rename/correction snapshots and prior mapping versions remain in append-only history. Store and source/station scopes and effective dates are validated; overlapping mappings for one source key are rejected. Hour targets remain disabled.

`GET/PUT /api/internal/import-directory/{CR2|CR3}` is an additive manager-only API using existing credential gates, bounded bodies, no-store responses and optional generated-type D1 binding. Production config is unchanged; absent service/binding displays unavailable instead of a false empty/saved result. There is no generic public record mutation route. Migrations 0001–0003 suffice; 0004 remains unused. No migration or deployment ran remotely.

The hours review retains every source row and raw external ID. Missing IDs use **exact source-byte SHA-256 + physical row number** as a review key; no name-derived or cross-file guess is made. Every row shows matched/unmatched identity. Same-name distinct source keys need explicit mapping before export; a missing external ID needs a reviewed shared UUID. The workbook keeps existing external IDs and source hour values; only a missing ID explicitly resolved by a manager is filled with that reviewed shared UUID. Ordinary unmatched nonambiguous legacy rows remain in the familiar workbook and visibly unmatched for later shared reports; they are never silently dropped or presented as a reviewed shared identity. Mapping revision/provenance are retained in optional device snapshots. These copies remain historical evidence, not a fresh server read.

Unsaved mapping choices are labelled working; only an authoritative response applies a saved mapping revision to the accepted hours review. Save uses one operation ID across an unchanged retry. Conflict/authorization/backend/network failure preserves working fields and old accepted source; download the working JSON, explicitly reload, compare and then save with the current revision. Reload asks before replacing unsaved mapping choices. No credentials are stored in directory, copies, logs or download bodies. Async context/generation checks prevent late responses or export completion from replacing newer work.
